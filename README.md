# Лабораторная работа №2

## Эмуляция распределённой корпоративной сети связи, настройка статической маршрутизации между филиалами

> Университет ИТМО | Факультет инфокоммуникационных технологий | Введение в маршрутизацию

---

### Описание

Компания "RogaIKopita Games" имеет офисы в трёх городах: **Москва**, **Франкфурт** и **Берлин**. Необходимо развернуть сеть из 3 роутеров MikroTik, настроить IP-адресацию, DHCP и статическую маршрутизацию для обеспечения полной связности между офисами.

### Схема сети

```
            PC3
             |
         R01.BRL
        (Берлин)
        /       \
   R01.MSK --- R01.FRT
  (Москва)   (Франкфурт)
      |            |
     PC1          PC2
```

### Технологии

| Технология | Назначение |
|------------|-----------|
| Статическая маршрутизация | Ручная настройка путей между подсетями |
| DHCP | Автоматическая выдача IP-адресов клиентам |
| ContainerLab | Эмуляция сетевой топологии |
| MikroTik RouterOS (CHR) | Операционная система роутеров |

### IP-адресация

| Канал | Подсеть | Маска |
|-------|---------|-------|
| Москва — Берлин | 10.10.1.0 | /30 |
| Москва — Франкфурт | 10.10.2.0 | /30 |
| Берлин — Франкфурт | 10.10.3.0 | /30 |
| Офис Москва | 192.168.10.0 | /24 |
| Офис Франкфурт | 192.168.20.0 | /24 |
| Офис Берлин | 192.168.30.0 | /24 |

### Структура репозитория

```
├── lab2.yaml              # Топология ContainerLab
├── R01_MSK.rsc            # Конфигурация роутера Москва
├── R01_FRT.rsc            # Конфигурация роутера Франкфурт
├── R01_BRL.rsc            # Конфигурация роутера Берлин
├── lab2_report.md         # Отчёт с результатами
├── lab2_network_diagram.png   # Схема сети
└── lab2_ping_routes.png       # Результаты проверки связности
```

### Запуск

```bash
cd lab2
sudo containerlab deploy --topo lab2.yaml
```

### Результат

Все пинги между офисами проходят успешно — 0% потерь, полная связность между PC1, PC2 и PC3.
